## Concrete defect for P10

The current `linux-site-deployment/SKILL.md` combines a careful staging/authority contract (lines 52–121) with a legacy “The 8 Steps” section (lines 145–212) that contradicts it. The latter directs a clone into `/var/www/html`, invokes `sudo npm`/`sudo composer` builds, writes directly into the live Nginx configuration directory, and reloads immediately; it gives only Debian Apache paths/`a2ensite` even though the entrypoint declares Debian/Ubuntu and RHEL support. It also describes repo updater changes as mandatory without integrating the existing repo-sync authority boundary. This is a documented safety, portability, and correctness defect, sufficient for a bounded repair without any skill-count target.

The linked baseline `references/deployment-checklist.md` repeated the same defect and added `sudo rm -rf` as generic rollback cleanup plus unsupported claims that rollback was tested. It has been replaced with a staged evidence checklist. The linked Nginx template baseline also enabled two-year HSTS with `includeSubDomains; preload`, hard-coded public resolvers, an unverified cipher list, and an HTTP/2 syntax that is deprecated on newer Nginx. The template now starts without HSTS/stapling, leaves cipher choice unassessed, and documents version-specific HTTP/2 syntax.
